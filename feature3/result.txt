============================================================
[기능 3 - 상태 변화 분석 (State Change Analysis)] 재현성 & 결과
============================================================
※ 기능 3은 별도 학습이 없는 '룰 기반 집계' 단계입니다.
   기능 1(감정)·기능 2(공격성)의 출력 라벨과 채팅 로그를 입력받아
   발신자별 상태 변화(🟢🟡🟠⚪)를 판정합니다.
   따라서 result.txt에는 학습 metric(Accuracy 등)이 아니라
   재현성 설정·판정 기준·적법성 기록을 남깁니다.

[입력 / 출력]
- 입력 : 기능 1·2 모델이 라벨링한 채팅 로그
         (통합 노트북이 chat_log1_raw.json·chat_log2_raw.json 원문을 추론)
- 출력 : daily_report.json (날짜별 × 발신자별 상태 + 자연어 해석)
         통합 노트북이 outputs/<입력명>_<실행시각>/ 폴더에 저장

[재현성 설정]
- Seed   : 42 (라벨 검수 미리보기 랜덤 샘플 — random.seed(42))
- 기준일 : 입력 데이터의 최신 날짜를 '오늘'로 자동 설정 후 직전 7일과 비교
- 시간대 : KST (Asia/Seoul, UTC+9)

[판정 기준 (가드레일 상수)]
- MIN_MSG_COUNT           = 10   (오늘 메시지 최소 — 미달 시 ⚪ 데이터 부족)
- MIN_BASELINE_MSG_COUNT  = 10   (직전 7일 누적 최소)
- NEGATIVE_THRESHOLD      = 5%p  (부정 비율 변화량 임계값)
- AGGRESSION_THRESHOLD    = 5%p  (공격성 비율 변화량 임계값)
- PARTICIPATION_THRESHOLD = 20%  (참여량 변화율 임계값)
- 종합 상태 : 주의 지표 0개 🟢 / 1개 🟡 / 2개 이상 🟠

[최종 결과]
- 통합 노트북(colab_feature3_member1.ipynb)이 기능1·2 모델로 실데이터
  (chat_log1_raw.json·chat_log2_raw.json)를 라벨링한 뒤 날짜별 × 발신자별 상태를 판정.
- 산출물은 입력 로그별로 outputs/<입력명>_<실행시각>/ 폴더에 분리 저장.
- 실제로 돌려 나온 결과물은 chat_log_result/ (chat_log1/ · chat_log2/) 에 보관.

[적법성 확인]
- 학습/검증/테스트 데이터셋을 사용하지 않음 (별도 학습 없음).
- 입력은 기능 1·2 모델의 출력 라벨과 채팅 로그뿐 (테스트셋 누출 해당 없음).
- 정답 라벨이 없는 실데이터이므로 Accuracy/Macro-F1 등 정량 metric은 산출 대상이 아님.
  (모델 자체 성능은 기능1 result.txt / 기능2 test_result.txt 에서 정답셋으로 측정)
